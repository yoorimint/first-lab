# 자동 운영 넘겨받기 계획 (운영자 지시 11/5)

> "울트라 요금 쓰는 동안 시스템 세팅을 끝마치고, 한 달 뒤 3만 원 요금제에서는 감시 세션 없이 알아서 돌아가야 한다."

- 지금(~12/5경): 비싼 요금제 + 35분 감시 세션(외부 검수·수정·재발 방지)
- 넘긴 뒤: 3만 원 요금제의 **예약 글쓰기만** + 서버 코드. 감시 세션·외부 검수 없음.
- 원칙: 감시 세션이 손으로 하던 일은 넘기기 전에 **전부 코드·테스트·글쓰기 지시 안으로** 옮긴다. 남는 사람 일은 비밀값 넣기·결정뿐.

## 감시 세션에 기대고 있는 일 → 넘기는 방법 (진행 상태)

| 지금 감시 세션이 하는 일 | 넘긴 뒤 누가 | 상태 |
|---|---|---|
| 새 글 외부 검수(opus)·수정 | 글쓰기 작업 안의 검수 단계 + 서버 관문(review_gate)·근거 대조(source_check) | 진행: 외부 검수에서 나오는 오류가 글당 0~1개가 될 때까지 유형을 코드·검사로 옮김 |
| 계산기 검수 | 계산기 검사기(tests/test_calculators.mjs): 기준선·10원 끝수·소수 자판·잘못된 입력 | 진행 |
| 법령 바뀜 감시 | 서버 law_watch(법제처 API) → 글 갱신 대상 표시 → 글쓰기 작업의 갱신(refresh) | 완료 |
| 공개 직전 확인 | 서버 freshness | 완료 |
| 글감·황금 키워드·성수기 | 서버 discover + naver_hub (매일 새벽) | 완료 |
| 금리 최신값·기준금리 변경 시 글 재검증 | 서버 bok_api (매일 새벽) | 완료 |
| 새로 생긴 혜택 글감 | 서버 benefit_watch (매일 새벽) → 글쓰기 세션 | 완료 |
| 공공 API 상태 확인 | 배포 점검 결과를 봇 기록에 남김 (/maintenance) | 완료 |
| 배포 실패 확인 | 15분 따라잡기 배포 + 실패해도 사이트는 마지막 정상판 유지 | 확인 필요: 실패 원인 자동 알림 |
| 고친 내용 실제 반영 확인 | verify_patches → 넘기기 전 서버 자동 점검으로 | 할 일 |
| 주간 표본 감사 | 넘긴 뒤엔 없음 → 넘기기 전 마지막 감사로 오류율 확인 | 할 일 |
| 사용량 | 연속 작성(하루 수십 편)은 3만 원 요금제에서 불가 → 예약 시각 방식(하루 N편)으로 | 할 일: 넘기기 1주 전 '3만 원 모의 운영'으로 하루 몇 편 가능한지 잼 |

## 넘기기 전 확인 (모두 통과해야 감시 세션 종료)
1. 최근 2주 새 글 외부 검수 오류가 글당 평균 1개 미만 (automation/reviewed.txt·patches.json 으로 셈)
2. '3만 원 모의 운영' 1주: 감시 세션 없이 예약 글쓰기만으로 글이 매일 올라오고, 관문·공개 직전 확인이 정상
3. 배포·봇 오류가 1주간 0건이거나 스스로 복구
4. 운영자에게 남는 일 목록이 비밀값·결정뿐 (아래)

## 넘긴 뒤 운영자에게 남는 일 (결정만)

## 검색·애드센스 위험 점검 (11/5 조사)
- 구글 '대량 생성 콘텐츠 남용(scaled content abuse)' 정책: AI 사용 자체가 아니라 '검수 없는 대량 생산'이 대상. 우리 대응: 공개는 하루 1편(승인 뒤 3편) 예약, 공개 전 독립 검수·관문·공개 직전 확인, 고유 도구(계산기), 검수 원칙 페이지, 수정일 표시. 공개 속도를 갑자기 크게 올리지 않는다.
- 애드센스: 공식 글 수 기준 없음. 필수 페이지(소개·문의·개인정보처리방침·이용약관) 갖춤 — 이용약관(면책) 11/5 추가.
