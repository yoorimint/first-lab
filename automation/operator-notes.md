# 운영자 지시 기록 (최신이 위)

다른 세션이 이어받을 때 읽는다. 운영자가 한 말 중 지금도 유효한 것만, 짧게.

## 말하기·일하는 방식
- 항상 **한글로만** 말한다 (중간 안내 포함). 짧게, 바꾼 것과 결과만.
- 나는 시스템 설계자: 오류는 말하기 전에 찾아 고치고, **고칠 때마다 다시 안 생기게** 코드·테스트로 막는다. 묻지 말고 처리 후 보고.
- 운영자에게 수작업을 시키지 않는다 (비밀값만 서버 `set-secrets.sh`). 비밀번호·키를 채팅으로 받지 않는다.
- 글쓰기 규칙(지시서)은 늘리지 않는다 — 많으면 할루시네이션이 는다. 코드로 막는다.
- 중요한 제품 결정(디자인 방향 등)은 운영자에게 묻는다.

## 감시·검수 (11/4)
- 35분마다 감시, **새로 만든 초안은 전부 바로 외부 검수** → 결과는 내가 한 번 더 훑고 수정 + 재발 방지. 그만하라고 할 때까지.
- 검수자는 Opus 로 지정.
- 초안 단계에서 완벽해야 함: 공개는 시간이 되면 내보내기만 한다. 이미 끝난 초안을 공개 직전에 다시 검수하는 방식은 원하지 않음.
- 11/5 운영자: 대기 초안 상한은 두지 않음, 애드센스 승인 뒤 하루 3편 공개 예정. 조문 번호 없는 예전 초안도 공개 직전 확인(근거 법령 부칙 시행일이 검수 뒤면 보류).
- 11/5 운영자: 초안과 공개 사이에 법·안내가 바뀔 수 있음 → 공개 직전 '코드' 확인만 (Claude 재검수 아님, bot/freshness.py): 근거 조문이 검수일 뒤 개정·시행됐거나, 쓸 때 공식 페이지에서 확인된 숫자가 사라졌으면 공개 대신 보류 → 글쓰기 세션이 보류 수정.

## 결정된 것

- 글: Claude 월정액 예약 작업으로 작성 (API 비용 추가 없음, Gemini 도 안 씀). 네이버 API 는 11/5 운영자 승인으로 NAVER API HUB 검색어 트렌드·블로그 문서 수만 (하루 상한, 유료 전환 시 끔). 그 밖의 네이버 검색 API 제안 금지.
- 연속 작성(시작/정지 버튼)으로 초안을 쌓고, 예약 공개 시각(± 랜덤)에 오래된 초안부터 공개.
- 사진: 글마다 AI 대표 사진 1장 (홈 목록·공유 미리보기). 본문 안에는 사진 없음, 글 화면 맨 위에 대표 사진 1장 (11/4 운영자 결정, 제목 카드는 숨김). 글자 깨진 사진은 자동 사진 검사로 교체.
- 홈: 큰 대표 글 1개 + 사진 목록. 대표 글 = 고정 글 → 서치콘솔 클릭 1위 → 최신.
- 상단 메뉴는 '계산기' 하나. 소개·문의·개인정보는 바닥글.
- 표: 휴대폰 폭에 안 들어가면 카드 모양.
- 계산기: 키워드에 '계산기'가 있으면 만든다. 상위 글 분석은 질문·목차만 참고(문장·사실 복사 금지).
- 애드센스 승인 뒤: 광고 지연 로딩(속도), 쿠팡 하단 고정 배너(대가성 문구, 애드센스 앵커 광고와 겹치지 않게).
- 댓글 끔.
- 법령 감시 확장(11/5): 입법예고(국민참여입법센터, 확정 아님 → 지켜볼 목록), 시행 예정 판(법제처 공개 데이터 — 운영자 무료 사용 신청 후 OC 를 set-secrets.sh LAW_OPEN_API_OC 로 넣으면 작동, 넣기 전엔 현행 판 부칙만).
- 11/5 운영자 승인: ① 법령 변경 감시(bot/law_watch.py, 매일 수집 작업 끝): 곧 시행될 근거 법령 개정 → /next law_changes 로 '바뀌는 제도' 글감, 막 시행된 개정 → 그 법 근거 공개 글 재검증(refresh 최우선). ② 계절 공개 순서(bot/seasons.py): 예약 시각은 그대로, 시즌 중 글 먼저·시즌 지난 글 뒤로. ③ 지원금·혜택 찾기 진단기: 다른 에이전트가 만들고 감시 세션이 모든 경우의 수로 검수.

- 소셜 자동 연동(인스타·X·스레드·틱톡·유튜브, 11/5 검토): 정보 검색형 글이라 소셜 유입 효율 낮음·플랫폼이 외부 링크 억제·계정·앱 심사 수작업 많음 → 보류. 애드센스 승인 뒤 스레드 하나로 2~4주 유입 추적 시험, 효과 있으면 확대.

## 11/5 공공 API (운영자 신청 완료)
- 법제처 국가법령정보 OPEN API: 서버 비밀값 `LAW_OPEN_API_OC`, 등록 IP 115.68.229.136·도메인 first-lab.kr. 서버는 직접, 다른 세션은 사이트 통로 `/wp-json/firstlab/v1/law` (토큰). 코드 `bot/law_api.py`.
  - 법령 ID 로 본문을 받으면 아직 시행 전인 판이 올 수 있다 → 현행은 `versions()`(시행일 기준 목록) + `current()` 로 고른다.
  - 조문 확인: `python3 -m bot.lawtext <법령명> <제N조>` 가 API 우선 (현행 판 + 시행 예정 개정 표시), 안 되면 화면 읽기.
- 공공데이터포털 '대한민국 공공서비스(혜택) 정보': 서버 비밀값 `DATA_GO_KR_KEY`, 통로 `/wp-json/firstlab/v1/benefits`. 코드 `bot/benefit_api.py` (`python3 -m bot.benefit_api serviceList perPage=3`).
- 배포 기록 '공공 API 점검' 줄에서 두 API 상태 확인.
- NAVER API HUB (네이버 클라우드): 서버 비밀값 `NAVER_HUB_ID`·`NAVER_HUB_SECRET`, 코드 `bot/naver_hub.py`. 무료인 동안 하루 블로그 2만·트렌드 300회까지 (운영자 지시: 한도 다 써서 키워드 창고 전체 훑기, 유료 공지 나오면 `ENABLED = False`).
  - 황금 점수: 아래 '정면 경쟁' 줄 참고. 글감 점수에 ×2 (황금 높은 것부터). 정보 검색만 대상(수식어·돈 주제 — 11/5 첫 조회에서 상품명이 황금으로 올라와 막음), 사이트 찾아가는 검색(로그인·고객센터 등) 제외, 글 10개 미만은 '확인 필요' 표시. 네이버 문서 수는 단어가 모두 든 글 수(따옴표 무관, 11/5 확인: 111,188 vs 111,185).
  - 매일 키워드 수집 끝(run_daily): 돈·계산기 주제·검색량 순 1만9천 개 문서 수 → 상위 후보·대표 주제 성수기. 황금·좋음 키워드는 오래돼도 안 지우고, 롱테일 조합을 먼저 만든다(검색 1,000부터).
  - 한계: 네이버 블로그 기준 경쟁도(구글과 같지 않음), 네이버가 붙여 쓴 말을 나눠 세는지 배포 점검 '네이버 문서 수 비교' 줄로 확인.

- 11/5 운영자 지시: 황금 키워드는 점수 높은 것부터 쓰고 공개. 글감 후보는 황금·좋음 무리가 맨 앞(그 안에서 점수순, select_keyword), 공개 순서는 시즌 지난 글만 맨 뒤로 두고 황금 점수×2+성수기 높은 글 먼저(schedule.publish_next, naver_hub.publish_priority).
- 11/5 황금 점수 경쟁도 (운영자 '그렇게 하는 게 맞나?'에 다시 검토): 네이버 전체 문서 수는 붙여 쓴 롱테일을 부풀리고, 상위 비율을 전체에 곱한 추정도 관련도순이라 부풀림이 남음 → 상위 30개 중 제목에 키워드가 그대로 든 '정면 경쟁 글 수'(hits)를 그대로 씀. 2개 이하 황금, 8개 이하 좋음, 25개 이상 포화, 정면 경쟁 글이 1년 넘게 낡았으면 가점. 황금 점수 = log10(검색량) × (1 − hits/30) + 0.5 × 낡은 비율. 한계: 다른 표현의 같은 뜻 제목은 못 셈.
- 11/5 황금 점수 최종 (운영자 '공부하고 와라' → 조사): 공식 정답 없음. 한국 도구(키워드파인더 등)는 검색량÷문서수(×100≥30 황금), 해외 KGR 은 제목 일치 글 수÷검색량(<0.25), Ahrefs·Semrush 는 상위 10개 백링크(유료라 못 씀). → 표준 황금지수(검색량÷문서수, 0.3↑ 황금·0.1↑ 좋음)와 정면 경쟁(상위 30개 제목 일치, 2↓ 황금·8↓ 좋음) 둘 다, 하나라도 기회면 인정. 점수 = log10(검색량) × max(min(지수/0.3,1), 1−경쟁/30) + 낡은 경쟁 가점. 12/3 이후 서치콘솔 노출·클릭으로 어느 지표가 더 맞혔는지 비교해 비중 조정.
